# 用户流程

## 1. 核心使用方式

Stella Fitness 必须顺着真实训练行为，而不是要求用户为 AI 改变训练习惯。

### 训练日

```text
打印/查看既定计划
  ↓
训练 + 纸笔记录
  ↓
训练结束
  ↓
拍训练日志
  ↓
系统结构化并标记不确定字段
  ↓
仅必要时请求最小补充
```

训练过程中不要求逐组手机输入，也不设计“每做一组和 Agent 对话”的默认流程。

### 体重

用户以低成本形式定期输入：

```text
今天 68.4 kg
```

系统保留原始测量时间和修正记录，用趋势而不是单次数字做判断。

### 饮食

饮食记录是可选证据，而不是强制打卡。

优先级：

1. 用户确认的食物重量 / 包装营养标签；
2. 固定食谱或已校准常吃餐；
3. 文字描述 + 份量信息；
4. 单张食物照片估算。

照片输入必须输出识别项、估算区间、置信度与不确定来源，不得伪装为精确计量。

## 2. 周期监督

```text
新数据进入
   ↓
更新事实与指标
   ↓
证据是否达到分析门槛？ ── 否 → 静默/继续收集
   ↓ 是
Blind Diagnosis
   ↓
Audit + Policy Gate
   ↓
NO_CHANGE / OBSERVE → 静默或简短周报
COLLECT_MORE_DATA   → 只问最高价值缺失信息
ADJUST_*            → 给出有证据的调整建议
ESCALATE            → 停止增肌优化，转安全提示
```

## 3. 典型场景

### 正常进展

体重与训练表现符合预期，没有连续异常。

结果：`NO_CHANGE`。系统不为了显示存在感而改变训练。

### 用户带着结论提问

用户：“我觉得就是吃少了，是不是应该加碳水？”

流程：

1. 原话中的观点不进入 Blind Diagnostician；
2. Blind Diagnosis 先基于 EvidencePacket 完成；
3. Belief Extractor 单独提取“摄入不足 → 加碳水”的用户观点；
4. Auditor 比较观点与已冻结诊断；
5. Policy Gate 决定是否允许调整。

### 日志照片看不清

只请求无法可靠恢复的最小字段，例如：

> “硬拉重量这一格无法可靠识别，请补充一个数字。”

而不是让用户重新手工录入整份训练。

### 数据不足

若 14 天内只有一次体重或饮食覆盖过低，系统应明确 `COLLECT_MORE_DATA`，而不是猜测停滞原因。

## 4. 非目标流程

- 实时动作视频纠正；
- 训练中持续语音陪练；
- 自动生成随机每日训练；
- 强制精确卡路里记账；
- 诊断疾病/伤病；
- 用情绪鼓励代替证据判断。
